Problem and Goal

Rule-based generation works, but it misses design intent

Research problem

  • Current mappings from UML to interface metadata are fixed and predictable.
  • Generated UIs have limited awareness of roles, workflows, objects, and usability intent.
  • Enterprise scenarios need multi-user, task-driven, object-centered interfaces.

Research objective

  • Use LLM reasoning to generate richer interface metadata from class, use case, and activity models.
  • Apply OOUI principles while remaining compatible with AI4MDE's Django generator.
  • Support human-in-the-loop refinement for designer feedback.

Interface Metadata DSL

Domain-Specific Language keeps AI output expressive and structured

{
  "interface": {
    "name": "Order Management",
    "actor": "Administrator",
    "intent": "manage orders and inventory"
  },
  "pages": [
    {
      "id": "orders-page",
      "name": "Orders",
      "object": "Order",
      "layout": { "type": "master-detail", "gap": "normal" },
      "sections": ["order-list", "order-detail"]
    }
  ],
  "sections": [
    {
      "id": "order-detail",
      "class": "Order",
      "objectRole": "primary-object",
      "attributes": ["status", "totalPrice", "createdAt"],
      "operations": ["Update", "Delete"],
      "workflow": {
        "activity": "Process Order",
        "state": "Processing",
        "editableWhen": "actor == Administrator"
      },
      "ui": {
        "component": "detail-panel",
        "colSpan": 6,
        "density": "normal"
      }
    }
  ],
  "tokens": {
    "page.body.bg": "bg-slate-50",
    "component.card.border": "border-slate-200",
    "element.button.primary": "bg-blue-700"
  }
}

Design principles

  • Object-centered: pages are organized around domain objects such as Order, Product, or Customer.
  • Role-aware: actors from use case models determine visible operations and permissions.
  • Workflow-aware: activity model states guide editable/read-only UI behavior.
  • Constrained styling: tokens allow visual variation without unrestricted generated code.
  • Validation-ready: every class, attribute, operation, and layout value can be checked before rendering.
