Frontend → generated API: changes in this round
================================================

Frontend
- Interface editor: Save now uses the separate category/section/page
  endpoints (new file lib/features/interfaces/save.ts). The old single
  "content" route is gone.
- "Generate default interfaces" now calls POST /interfaces/default/.
- Versions tab (releases): list, create, delete, export, load, import from a
  file and import systems all go through api/metadata/releases.ts.
  If the project has unsaved changes, Load asks before overwriting.
- Exports page: the project and systems exports go through api/metadata/project.ts.

Backend: NEW ENDPOINTS (added by us, no database migrations)
- DELETE /releases/{release_id}/
- POST   /releases/import_systems/{project_id}/   (file, name, release_notes)
- GET    /projects/{project_id}/export/
- GET    /projects/{project_id}/systems/export/?system_ids=...
- Logic: metadata/services/versioning/systems.py (new)
- Tests: metadata/tests/versioning/test_added_routes.py (new)

Backend: cleanup
- Removed the unused InterfaceContent schemas and imports left over from the
  old content route.

Open (Maarten's code, not changed)
- routes/releases.py, import_release: error returns {" message": exc.message[0]}
  (leading space, and it should be exc.messages[0]), so a bad file gives 500.
